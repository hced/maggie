# SPEC.md: Maggie – Technical & Functional Specification

## 1. Project Overview & Scope
**Maggie** is a native Wayland screen magnifier and utility tool written in **Rust (Edition 2024)**. It is designed to run seamlessly on minimal desktop environments and tiling window managers (such as **Niri**) without relying on legacy X11 layers or fallback architectures.

---

## 2. Core Architecture & Environment
* **Language:** Rust (Edition 2024)
* **Display Server Protocol:** Native Wayland exclusively.
* **Task Management:** Managed via a project root `Justfile` (e.g., `just build`, `just run`, `just check`, `just test`).
* **GPU Acceleration:** Rendering is GPU-accelerated via **EGL + OpenGL ES 2** (`src/gpu.rs`): the frozen frame and OSD legend are drawn as textured quads and presented through a `wl_egl_window` at a 2× buffer scale. If EGL/GLES initialization fails, the app **automatically falls back to the CPU rendering path** (`src/render.rs`), which remains fully functional; the choice is made once at startup.

## 3. Screen Capture & Modes — *Implemented*
* **Frozen-frame model:** The screen is captured exactly **once** at startup via `zwlr_screencopy` (`capture_output` on the current output). The SHM buffer (XRGB8888/ARGB8888) is converted to RGBA with a stride-aware row copy, honoring the `y_invert` flag.
* **Capture-before-content:** The fullscreen layer-shell overlay (`Layer::Overlay`) is committed at startup but presents **no image data until the first captured frame is ready**; the initial screencopy therefore never contains the overlay, avoiding the Droste-effect self-feedback that plagues live-capture magnifiers.
* **Frozen view:** After the first frame, the overlay displays a nearest-neighbor zoomed view of the frozen frame. Zoom keys `1`–`9` re-scale the same frozen frame; the screen is never re-captured at runtime.
* **Fullscreen viewport at launch:** The viewport covers the **entire physical screen** from the very first presented buffer — including any shell bars (e.g., the Noctalia shell top bar) in the magnified capture — with **no compositor window rules** required. The layer-shell overlay is created on the **Overlay layer** (topmost) with **all anchors** and an **exclusive zone of −1** ("dont care"): without it, niri/Smithay shrinks the overlay geometry around the reserved zones of bars/docks (e.g., the Noctalia top bar) regardless of layer, leaving the real bar covering the magnifier's top strip. The surface explicitly requests the **full output logical size** and **re-asserts it on every configure**, **redrawing immediately** whenever a configure changes the size. The **GPU (EGL) window is initialized lazily at the first configure**, when the real output logical size is known, so the very first presented buffer is already fullscreen: creating the `wl_egl_window` with a hardcoded size and calling `wl_egl_window_resize` before the first `eglSwapBuffers` has no effect on the first attached buffer, which previously left the viewport smaller than the screen until the first pointer motion triggered a second swap (regression fixed in commit `99d2dd2`).
* **Failure handling:** A failed capture is retried up to **3 times**; if all retries fail, the overlay renders black.
* **Zoom centering:** The viewport follows the **live cursor** over the frozen frame — the view is centered on the content under the cursor; if the cursor was never seen, it centers on the capture. The **magnified cursor is always drawn at the dead center of the viewport** (in every mode, including while panning, zooming, easing or hold-zooming): only the magnified screen moves when the mouse moves. Zoom keys `1`–`9` re-scale.
* **Cursor-following motion:** The view is panned **relative to the hand's movement** (per-event deltas in logical pixels mapped into source space via per-axis source/viewport ratios `scale_x`/`scale_y`, so capture buffers whose aspect ratio differs from the output are handled correctly). The view center is never re-derived from the hand's *absolute* position after launch, so the view can never jump to the hand: **releasing hold-to-zoom (or any other state change) leaves the view exactly where it is**, and the next mouse motion pans it smoothly. The view center is initialized **once, on the first pointer enter, to the launch cursor's content** (a draw before the enter would otherwise leave it at the capture center), preserving the "start exactly where the cursor was" behavior; later pointer enters never re-center. Positions are tracked at sub-pixel precision, shifting the magnified content continuously on the CPU fallback (bilinear) and quantized to source texels on the GPU path (nearest-neighbor).
* **Input responsiveness during animation:** Keyboard input (the app's own global keys — zoom/OSD/screenshot bindings) works even while the panning animation is running: the **EGL swap interval is set to 0** so frame redraws never block the event loop. The layer surface's keyboard interactivity is **`on-demand`** (not `exclusive`), so compositor-level global keybindings keep working.
* **Viewport rendering:** The viewport is rendered from the frozen frame as a textured quad. The **GPU path** samples the frame texture with **nearest-neighbor** filtering into a buffer at **2× the layer's logical size** (`wl_surface.set_buffer_scale(2)`), yielding the crisp, pixelated magnifier look. The **CPU fallback** (`src/render.rs`) renders with **bilinear interpolation** at fractional source offsets, shifting the magnified content continuously. Both paths paint the region beyond the capture **solid black** (the view *region* is not clamped — the view center is, so near the screen edges the region samples past the frozen frame while the cursor stays inside the capture).
* **Scroll-wheel zoom:** The scroll wheel zooms in/out in one of two modes selected by `scroll_zoom_mode` (§4): **`levels`** (**default** — each notch steps between the discrete levels of the `1`–`9` keys: level *i* = `max_zoom` × *i*/9, so the wheel spans 1×..`max_zoom`; on a level it steps to the neighbour, off a level it snaps to the next level in the scroll direction) or **`factor`** (each notch multiplies the zoom by **10 %**, clamped to 1×..`max_zoom`). By default the wheel direction is reversed compared to conventional zoom (wheel-up zooms **out**, wheel-down zooms **in**); the `invert_scroll_zoom` option (§4) flips back to the conventional direction (wheel-up zooms in). High-resolution `value120` wheel deltas are supported; continuous touchpad scroll is ignored.
* **Hold-to-Zoom:** While the **`hold_to_zoom`** modifier (default **`Space`**; was `Super` — existing configs migrate) is held, **vertical pointer motion zooms continuously** — moving up zooms in, down zooms out, at a rate of `hold_to_zoom_speed` zoom-units per pixel (default 0.05, so the full 1×–9× range takes 160 px of travel) — clamped to 1×..`max_zoom`. The zoom change is **position-based per motion event**, so it stays buttery-smooth at any event rate (no stepping, unlike the wheel's level/factor modes). **Horizontal motion is unaffected**: it still pans the view normally. The modifier press arms the feature with the current pointer Y as baseline (no initial jump); releasing it disarms; while the Configuration window is open it is forwarded to egui and does nothing. **No drift, no jumps:** while held, vertical motion **only** zooms and horizontal motion **only** pans — so the view y stays locked to the content under the centered cursor and the **magnified cursor never leaves the dead center of the viewport**: the same guarantee a wheel zoom gives, at any zoom. On **release** nothing is repositioned and nothing re-centers: the view stays exactly where it is and the next mouse motion pans it by its relative delta — **no jump at release and no jump on the first motion after release**. **Offset correction:** because the view y was locked while the hand travelled to zoom, release leaves the view offset from the hand's content; left alone, that offset shifts the reachable pan range and creates invisible limits. The residual offset is therefore **derived continuously** (view minus hand content, recomputed on every motion event) and **corrected by subsequent real pointer motion** — each motion event pulls the view a small fraction of the remaining offset back toward the hand content (exponential decay, τ ≈ 0.8 s of movement; the per-event correction is capped both in time and by the hand's own per-event travel, so a pause followed by a small nudge can never lurch the view) — restoring the full pan range **without any jump or self-animation** (nothing moves unless the hand moves). **Reach-restoring boost:** a residual always blocks the wall in the direction it points away from — pushing there used to stop short by the residual (an "arbitrary distance" that grew with fast motion, because a quick push to the wall gave the slow decay no time to finish). So whenever the pointer moves **toward the hand content** (the reach-blocking direction), the correction is boosted to at least the hand's own per-event travel (capped at 2× the hand's speed, never overshooting the hand): the residual is erased **during the push itself**, so the far wall is reached **exactly, at any speed, immediately after hold-to-zoom** — with no jump and no self-animation (the view never moves unless the hand does, and never faster than 2× it). Moving away from the hand content heals gently (time-based only) and never fights the user. **The correction never fights a wall:** the view is hard-clamped to the capture *before* correction, and any axis already pinned against a capture edge is left untouched by the correction — so pushing against a screen edge always lands the view **exactly** on the edge, and gliding along an edge keeps the view on it, regardless of pointer speed or the size of the residual offset. **Hand-edge reach:** the view pans with the hand's *movement*, so its reach is bounded by the hand's delivered travel — and the compositor's **last delivered pointer position can lag the hand's true stop by up to one event's travel when the pointer is moved fast** (the delivered position is the last sample before the hand actually stops), which is exactly why walls used to stop short at speed while slow motion always reached. So when the pointer is **pushing toward a wall this event, the reach margin scales with the event's own travel** (`|delta| × 1.5 + 8` logical px, capped at 120): the margin is small when the pointer is moving slowly (no magnetic wall — parking stays precise anywhere) and large exactly when the delivery gap is large, so the view is placed **exactly on the capture edge at any speed**. The view must already be within the (scaled + 8 px slack) margin of the wall, so any jump stays the size of the delivery gap, never a large hold-to-zoom residual that is still healing. Pushing away, gliding, and mid-screen motion never trigger it; the near-edge diagnostic log (`RUST_LOG=maggie=debug`) reports the pointer, view, residual, delta, and the computed reach margin so the margin can be tuned against real delivered-position gaps. In steady state the offset is exactly zero (the view pans 1:1 with the hand), so the correction is dormant during normal panning — but it is always armed, so **any** residual offset (hold-to-zoom, a launch race, a resize) self-heals during motion — a pinned axis holds the exact edge while the user is on it, and its residual resumes decaying once the view moves off the wall (or once the hand catches up to the edge, at which point hand and view pin to the same value and the offset is zero). **Edge space:** because the cursor sits at the viewport center, the view may need to **sample past the frozen capture** near the screen edges — that region is always painted **solid black**.
* **Viewport edges:** The **view center never leaves the capture bounds** — it is hard-clamped to `0..capture_w × 0..capture_h` on every write (motion, hold-to-zoom, launch centering, and again in the render path as a final invariant). Because the magnified cursor sits at the viewport center (= the view center), this guarantees the cursor **never enters the black beyond-capture fill** and that **every captured pixel stays reachable** — pushing against a screen edge always lands the view exactly on the capture edge, so repeated left-right/top-bottom travel can never accumulate a reachable-range shift (no invisible limits). The magnified *view region* itself is not clamped: near the screen edges it still samples past the frozen frame, showing **solid black** beyond the capture; the cursor simply never sits in that black zone.
* **Magnified cursor (Implemented):** While the pointer is over the viewport, the **hardware cursor is hidden** (a blank 1×1 transparent ARGB cursor surface is set on `wl_pointer` enter, restored on leave) and the **real system cursor bitmap is drawn magnified**. The frozen frame can never contain a baked copy of the system cursor because the screencopy is requested with **`overlay_cursor = 0`** — the wlr-screencopy protocol requires the compositor to exclude the cursor from the capture (honored by niri, wlroots, KWin, Hyprland, …), independent of pointer focus or timing. The **first capture is requested at the first configure, before anything has been rendered** — the frame appears immediately after launch, contains no feedback copy of the magnifier's own overlay (nothing has rendered yet), and the view centers exactly on the pointer's launch position when the pointer enters the surface. *inside* the view at the exact spot where the content under the pointer lands. On startup the cursor theme is loaded from disk (`$XCURSOR_THEME`, default `default`/`Adwaita`, via the standard icon search paths) and parsed with the `xcursor` crate; the pointer's **hotspot** is honored, so the arrow tip lands exactly on the content under the cursor. The image is **nearest-neighbor upscaled by the zoom level** (and the 2× render buffer on the GPU path), so it magnifies along with the visuals. It **tracks the live pointer on every motion event** (never a static sprite). If no theme is found, it falls back to a stylized reticle (white ring, black center). Rendered on both the GPU path (alpha-blended textured quad via the sprite shader, pre-scaled to the 2× render buffer) and the CPU fallback (alpha-blended blit, `MagnifierWindow::draw_cursor_at`). See §5.
* **No live mode:** Continuous live capture is explicitly **out of scope**; the interactive live-magnifier idea (including an earlier planned `--live` flag) was dropped. Behavior modes that assumed a live view (see §6) are obsolete until redefined.

## 4. Configuration System — *Partial*
* **Location:** XDG standard configuration directory (`~/.config/maggie/`).
* **Format:** `.ron` (Rusty Object Notation) configuration file.
* **Storage Requirements:**
  * **Default Zoom Level** (floating point, clamped to `max_zoom`).
  * **Max Zoom Level** (`max_zoom`, floating point, default `9.0`, range 1×–32×): the ceiling for the zoom keys, the scroll wheel, hold-to-zoom, and the default zoom.
  * **Hold-to-Zoom Speed** (`hold_to_zoom_speed`, floating point, default `0.05` = 5 % zoom per pixel of vertical motion, range 0.001–1.0): rate of the smooth hold-to-zoom feature — see §3.
  * **Scroll-Wheel Zoom Mode** (`scroll_zoom_mode`): `levels` (default) | `factor` — see §3.
  * **Invert Scroll-Wheel Zoom** (`invert_scroll_zoom`): boolean, default `false` — see §3.
  * **OSD Visibility** (`show_osd`): boolean, default `true` — see §7.
  * **Keybindings** for all in-app functions. Defaults: `toggle_osd` `K`, config window **`Tab`** (was `C`), `toggle_cursor` **`C`**, `hold_to_zoom` **`Space`** (was `Super`; old files migrate), `reset_zoom` `R`, screenshots `F`/`S`/`W`, anti-aliasing `A`.
  * **Screenshot Path** (default: `~/Pictures`).
  * **Screenshot Filename Pattern:** Utilizes standard `strftime` formatting tokens (supporting dynamic variables such as `%Y` for year, `%m` for month, `%d` for day, `%H` for hour, `%M` for minute, etc., defaulting to `maggie_%Y%m%d_%H%M%S.png`).
* **Serde defaults:** Newer options (`scroll_zoom_mode`, `invert_scroll_zoom`, `show_osd`, `max_zoom`, `keybindings.reset_zoom`, `keybindings.toggle_cursor`, `keybindings.hold_to_zoom`) carry `#[serde(default)]`/`#[serde(default = …)]`, so config files written before these options existed remain loadable (unknown/removed fields like `cursor_follow`, `htz_edge_behavior`/`htz_edge_fill` are ignored by ron); `max_zoom` and `default_zoom` are normalized on load (NaN/out-of-range values dropped, default clamped to the max).
* **Status:** Loading from disk is implemented; the listed `strftime` tokens are evaluated on save. Persistence is wired through the Configuration window (§9) — changes are auto-saved on change (snapshot drift detection); the explicit **Save** button also writes.

## 5. Visuals & Rendering — *Implemented* (AA toggle: *Stub*)
* **Zoom & Scaling:** Controlled via numeric keyboard keys `1` through `9` — each key selects a **percentage of the configured max zoom** (key *i* = `max_zoom` × *i*/9, so key 9 is always the maximum; with the default `max_zoom = 9` the keys map to 1×..9× exactly as historically) — or the scroll wheel (`levels` mode: steps between those same levels; `factor` mode: 10 % steps up to `max_zoom` — see §3). The **middle mouse button** (and the `reset_zoom` keybinding, default `R`) resets the zoom to the **default zoom**; keys and wheel re-scale the frozen frame.
* **Rendering Preference:** The default **GPU path** (EGL/GLES2) renders the viewport with **nearest-neighbor** sampling at a **2× buffer scale** for a crisp, pixelated magnifier look; sub-pixel cursor-following is then quantized to source texels (see §3). The **CPU fallback** uses **bilinear interpolation**, which shifts the magnified content continuously during sub-pixel cursor movement. The active path is selected automatically at startup — GPU if EGL/GLES2 initializes, CPU otherwise (see §2).
* **Anti-Aliasing Toggle:** An optional toggle bound to the `A` key, implemented only if it does not introduce development complexity. — *Stub: key is bound but not yet functional.*
* **Magnified cursor rendering:** `src/cursor.rs` (`MagnifiedCursor`) loads the **system cursor theme bitmap** at startup (`xcursor` crate parses the `.cursor` file; premultiplied ARGB pixel data is converted to straight alpha) and caches it as the base image. Each frame it is **nearest-neighbor upscaled** by `zoom × render_scale` into an RGBA buffer; the image's **hotspot** (scaled identically) is passed to the renderer so the cursor tip tracks the content under the pointer. Its visibility inside the viewport is toggled with the **`toggle_cursor`** key (default `C`, separate from the hardware-cursor hiding). **Why load the theme file instead of the live cursor:** Wayland exposes no protocol to read the compositor-drawn hardware cursor bitmap, so the app reads the same theme files the compositor uses from disk. The sprite is composited above the magnified frame and below the OSD legend. On the GPU path it is drawn with a dedicated sprite vertex shader (rect placement in `u_rect`, explicit NDC y-flip, full-texture sampling) at `RENDER_SCALE` resolution so it matches the crisp 2× buffer; on the CPU path it is blitted at logical scale (`MagnifierWindow::draw_cursor_at`).

## 6. Behavior Modes — *Revised*
* The former **Center Cursor** / **Edge Pan** / **Miniature Window** modes remain **obsolete/removed** in the frozen-frame model; they are pending redefinition or removal. Mode-switch bindings (`Ctrl+C`/`Ctrl+E`/`Ctrl+M`) still exist in code but have no rendering effect.
* **Cursor-following:** The former "Center Cursor" concept is now the **built-in default behavior** of the frozen viewport — the view follows the live cursor over the frozen frame with the magnified cursor always pinned at the viewport center; near the capture edges the view extends past the frame (black fill). See §3.

## 7. OSD (On-Screen Display) Key Legend — *Implemented*
* Toggable via the `K` key (configurable via `keybindings.toggle_osd`).
* **On by default**, configurable via the `show_osd` configuration file option (§4).
* Dynamically stays or moves out of the way of the cursor position: the legend box is placed in the **corner farthest from the cursor** (4-corner logic, considering the box center).
* The legend background is **opaque** (solid dark box, alpha 255) so no magnified content or text ghost shows through.
* Rendered with a built-in 5×7 bitmap font (`src/osd.rs`) drawn at **4× scale** (5×7 glyphs scaled 4×, i.e. rendered at 20×28) with doubled box padding/margin — the legend was enlarged 2× for readability; lists zoom level, `1`–`9` zoom, `K` OSD toggle, `F` fullscreen screenshot, `S`/`W`/`Tab` (config window), **`C` toggle cursor**, **`hold Super` + move smooth zoom**, **`MMB`/`R` reset zoom**, and `Q`/`Esc`/`RMB` quit.
* **Rendering fix:** The OSD quad is drawn with its own dedicated vertex shader that samples textures **top-down**, because the captured frame texture is stored **bottom-up** (screencopy `y_invert`) so the main shader's Y-flip compensates it. Previously the top-down OSD sprite was rendered upside down and outside its box, leaving only the opaque background visible as an empty black box; the legend text now renders upright inside the box.

Triggered using dedicated keybindings (`S`, `W`, `F`):
* **Manual Selection (`S`):** Allows dragging a rectangular selection region. Once drawn, the side closest to the mouse cursor can be nudged using the **Arrow keys** (1 px per keypress). — *Stub: not yet implemented.*
* **Window Selection (`W`):** Displays a dynamically sized grid representing all available windows for capture. Clicking an item captures and saves that specific window. — *Stub: not yet implemented.*
* **Fullscreen Capture (`F`):** Saves the currently frozen frame as a PNG. — *Implemented.*
* **Cancellation:** Pressing **Escape** during Manual or Window selection mode cancels the operation. — *Pending together with `S`/`W`; Escape currently quits the app.*
* **Output Path Generation:** Combines the configured `screenshot_path` with the evaluated `strftime` filename pattern (`~` expansion and directory creation included). — *Implemented.*

## 9. Configuration Window — *Implemented* (GPU path)
* Activated via the **`Tab`** key (`keybindings.config_window`; changed from `C` so `C` could become the magnified-cursor toggle); closed with the **Close** button or **Escape**.
* Built with **egui 0.35 + egui-glow** (`src/config_window.rs`) painted directly into the same EGL surface through a `glow` context sharing the app's GLES2 function pointers — no separate toplevel window is created (Maggie is a full-screen layer-shell overlay). Requires the **GPU render path**; on the CPU fallback the key logs a warning.
* While open, the whole surface shows the UI, **pointer and keyboard events are forwarded to egui** (motion, buttons, wheel, keys via an xkeysym→`egui::Key` mapping, text input, modifiers), and the magnifier's own key handling (zoom keys, Q/Esc quit) is suspended. Keyboard interactivity stays **`on-demand`** throughout (never toggled): niri grants it at map time and on every click, so text fields receive keys after the first click — and critically, *not* switching to `exclusive` means niri never clears its remembered on-demand focus, so closing the window leaves the magnifier's global keys working immediately (an `exclusive`→`on-demand` round trip would drop focus until the next click).
* **Fonts:** The window uses larger base fonts (body 19 pt, headings 28 pt, small/hint 16 pt) for readability on the full-screen surface.
* **Exit guidance:** The footer explains that the window is closed with the **Close** button or **Escape**, that the magnifier's keys resume afterwards, and that `Q`/`Esc`/`RMB` quit Maggie when the window is closed.
* **Cursor while open:** The hardware cursor is replaced by a **real cursor surface built from the loaded system cursor theme** (`config_cursor_surface`; the straight-alpha theme bitmap is premultiplied into an ARGB8888 shm buffer, hotspot honored via `set_cursor`), so the UI shows a normal, visible pointer. It is re-asserted on every pointer **enter** (fresh serial) and on every **button press** (fresh serial) to defeat stale-`set_cursor`-serial drops by the compositor; the blank surface is restored on close. *Known quirk (unchanged): near Noctalia hot corners the pointer may briefly leave the surface and show the compositor cursor until it re-enters.*
* **Instant Application:** All settings are edited live (no separate Apply step) — `default_zoom`, `scroll_zoom_mode`, `invert_scroll_zoom`, `show_osd`, screenshot path/pattern, and all keybindings.
* **Persistence:** Changes are **auto-saved on change** — every frame the live config is compared against the last-persisted snapshot (`MagnifierConfig: PartialEq`); any drift (a modified field, a picked folder) is written to disk immediately, so settings survive restarts without clicking anything. The **Save** button still writes explicitly, **Reload** re-reads from disk and resets the snapshot, and a status line reports outcomes. `default_zoom` is normalized on load (NaN / out-of-range values dropped) so a hand-edited file cannot poison the drift check. The `default_zoom` field is edited through `get_or_insert` (a previous `unwrap_or` edited a temporary, so the setting silently never changed).
* **Folder picker:** A **Browse…** button next to the screenshot path opens a native folder-picker dialog (`egui-file-dialog` 0.14, `pick_directory`/`take_picked`) built **non-modal** (`as_modal(false)` — the modal overlay is a full-screen interactive backdrop that can sit above the dialog in a hand-painted egui setup and swallow all clicks, leaving only keyboard navigation); the chosen directory is applied to `screenshot_path` and auto-saved.
* **Settings covered:** `default_zoom` (clamped to `max_zoom`), `max_zoom`, `hold_to_zoom_speed`, `scroll_zoom_mode`, `invert_scroll_zoom`, `show_osd`, screenshot path/pattern, and all keybindings including **Reset zoom** (`reset_zoom`, default `R`; MMB does the same), **Toggle magnified cursor** (`toggle_cursor`, default `C`), and the **Hold-to-zoom modifier** (`hold_to_zoom`, default `Space`).
* **Animation timing:** `RawInput.time` is fed from a monotonic clock so egui animations (text caret blink) run at real speed instead of as-fast-as-frames-are-produced.
* **Factory Reset:** Per-setting reset buttons are *not* implemented (deferred); values can be reverted manually.

## 10. CLI Arguments — *Implemented*
The application supports the following command-line interface arguments:
* `-z` or `--zoom <LEVEL>`: Specifies a preferred initial zoom level (e.g., `3`).
* `-d` or `--debug`: Enables debug mode to output verbose troubleshooting logs to `stdout`.
* `--version`: Prints the program version.
* `--help`: Displays help documentation.
